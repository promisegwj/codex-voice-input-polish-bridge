# 语音转文字整理规则优化方案 v0.2.0

方案版本：v0.2.0  
生成日期：2026-05-27  
上游草案：`docs/voice-text-rule-optimization-plan.md` v0.1.0  
适用项目：`当前仓库目录`  
主负责人审批结论：有条件批准，收窄 MVP 后进入实施规划。
第二轮复议结论：继续批准 v0.2.0，但补充“阶段 0 为阶段 1 前置门槛”“最小回填状态闭环提前进入 MVP”“保护对象扩展到否定/条件/疑问/不确定性”等实施约束。

实施状态：2026-05-27 已落地 MVP 范围（阶段 0 + 阶段 1 + 最小回填状态闭环）。新增机器可读 golden case `tests/golden/voice-text-rule-cases.jsonl`、runner `tests/Run-VoiceBridgeGoldenCases.ps1`、整理器 `--version` / `--debug-decision`、保守 `StructureDecision` / `LiteralSpan` / 输出校验，以及回填接口稳定状态字段和页面状态文案。

## 1. 评审背景

本版规划是在 v0.1.0 草案基础上，经 6 个子模型角色评审后形成：

- 软件开发/架构专家
- 产品经理
- 语音转文字重度使用用户
- 隐私与安全负责人
- QA/可测试性负责人
- 中文语音/NLP 整理专家

评审共识很明确：v0.1.0 的方向正确，但不能把“更聪明的改写”放在第一优先级。新版规划必须先建立用户信任，核心是事实不丢、数字不误伤、该分条才分条、失败不误粘贴，并且每个阶段都能验证。

## 1.1 第二轮复议补充

2026-05-27 第二轮复议后，参会角色一致确认 v0.2.0 不需要推翻，但需要补强以下约束：

1. MVP 范围调整为：`阶段 0 + 阶段 1 + 最小回填状态闭环`。阶段 0 是阶段 1 的前置门槛，不是可选建议。
2. 所有会产生列表输出的旧路径都必须纳入统一结构决策和输出校验，包括项目专用格式化、已知项目提取和普通列表提取，不能有绕过新原则的特殊分支。
3. 结构判断必须基于原始口述或早期规范化文本，不能基于已经压缩、替换、提示词化后的文本。
4. `LiteralSpan` 不只保护数字、路径和版本号，也要保护否定、条件、疑问、反问、不确定性、优先级和专有名词。
5. golden case 必须机器可读，不能只停留在 Markdown 表格；测试入口必须能读取结构决策信息。
6. 页面最小状态闭环要提前进入 MVP：用户必须能清楚知道文本已进入 Codex 输入框、只在剪贴板，还是自动粘贴被跳过。
7. 当前本机配置里的自动应用、随 Codex 启动和发送后旁路确认属于个人机器已授权状态，不代表发布默认；发布默认应保持保守。

## 2. 主负责人审批结论

### 2.1 批准采纳

以下意见进入 v0.2.0 主线：

1. 先做“保守结构规划”，不继续单纯堆正则。
2. 在分条和压缩前保护日期、端口、路径、版本号、型号、快捷键、金额、百分比、容量、时间、数量范围等事实跨度。
3. `ShouldPreferStructuredPrompt` 不能再由默认整理规则中的“拆分、总结、要点、提示词”等词单独触发。
4. 增加内部结构决策对象，至少包含 `mode`、`shouldList`、`confidence`、`reasons`、`protectedSpanCount`。
5. 增加输出校验器。发现误分条、碎片化列表、事实跨度丢失时，回退为普通段落。
6. 块级清理口头禅，但必须保护判断、定义、解释、顺序和否定关系。
7. 建立 golden case 回归测试，并优先覆盖数字/路径/版本号误分条、明确枚举分条、口头禅清理、语义连接保护。
8. 回填失败时只保留剪贴板，不向未确认的焦点发送按键。
9. 页面状态必须清楚表达“正在整理”“已回填，可以发送”“失败，已复制到剪贴板”。
10. 阶段 0 必须提供机器可读 golden case 和结构决策调试入口，阶段 1 不应在缺少这些前置验证时开工。
11. 自动分条默认阈值为 `confidence >= 0.75`；低于阈值保持普通段落。

### 2.2 部分采纳

以下意见保留，但不进入第一阶段 MVP：

1. `conservative | structured` 模式：方向正确，但第一阶段默认只实现保守行为；显式模式开关放到后续阶段。
2. 完整自动应用体验优化：要继续做，但不能凌驾于事实保护和输出校验之上；第一阶段只提前最小回填状态闭环。
3. 持续学习：继续作为补充能力，不作为解决结构判断问题的主路线。

### 2.3 暂缓或不采纳

以下内容不进入默认路线：

1. 默认接入云端 LLM 全文重写。
2. 用本地小模型或云模型直接替代规则整理器。
3. 强行寻找或写入 Codex 私有 composer、SQLite、Electron 存储、named pipe 或未知 IPC。
4. 让持续学习自动改写整理器永久源码规则。
5. 默认要求用户每次审核或保存样本。

### 2.4 第二轮最终取舍

第二轮新增意见中，主负责人批准纳入当前实施依据的内容：

- 提前最小回填状态闭环：不完整重做 UI，但 MVP 必须至少区分 `正在整理`、`已回填到 Codex 输入框，可以发送`、`未回填，已复制到剪贴板，请手动粘贴`、`已跳过自动粘贴：未捕获目标 / 聚焦失败 / 用户关闭自动应用`。
- 统一列表出口：`TryFormatCalibrationRound`、`TryFormatReturnFlowTest`、`ExtractKnownVoiceBridgeItems`、`ExtractPromptItems` 等所有可能产出列表的路径都必须经过 `StructureDecision` 和输出校验。
- 扩展保护对象：除数字、路径、版本号外，否定、条件、疑问、反问、不确定性、优先级、专有名词、近音技术词和模糊数量表达也进入保护范围。
- 测试先行：先建立 `tests/golden/voice-text-rule-cases.jsonl` 或等价机器可读测试集，以及 `tests/Run-VoiceBridgeGoldenCases.ps1` 或等价 runner，再改结构判断。
- 固定回填响应语义：接口结果应稳定暴露 `copied`、`pasteScheduled`、`pastedImmediately`、`pasteSkippedReason` 等字段，跳过原因建议包含 `missing_paste_target`、`codex_composer_focus_failed` 等枚举值。

暂不纳入当前阶段的内容：

- 完整 UI 重构。
- 完整强整理模式。
- 默认开启 LLM/API。
- 把持续学习作为主流程。

## 3. v0.2.0 产品原则

1. 信任优先：不改坏，比看起来聪明更重要。
2. 保守默认：默认行为应是 `conservative`，只在高置信度下分条。
3. 事实优先：数字、路径、版本号、否定、条件、时间、文件名和专有名词不可因压缩而丢失。
4. 低打扰：校准和持续学习应是低频、主动、可跳过的补充流程。
5. 失败安全：回填失败可以接受，误粘贴和误发送不可接受。
6. 本地优先：不默认引入云端 API、API key、账号额度或第三方文本处理。
7. 可验证：每个阶段都要有明确用例和最小验证命令。
8. 不确定保留：不确定就不分条，不确定就不删除，不确定就保留原约束。

## 4. 新版技术规划

### 阶段 0：测试基线与可观测性

目标：先把判断标准固化，避免后续凭感觉调规则。

阶段属性：阶段 1 的前置门槛。

改动范围：

- 新增机器可读 golden case 测试样例文件，例如 `tests/golden/voice-text-rule-cases.jsonl`。
- 新增测试 runner，例如 `tests/Run-VoiceBridgeGoldenCases.ps1`，只测整理器，不碰剪贴板和真实 Codex 窗口。
- 新增 `--debug-decision` 或等价测试入口，输出结构判断摘要；测试至少能读取 `mode`、`shouldList`、`confidence`、`reasons`、`protectedSpanCount`、`protectedSpans`。
- 建议整理器补充 `--version` 或等价版本输出，便于测试报告绑定版本。

验收标准：

- 至少覆盖本文件第 7 节的最小测试集。
- 测试能区分“自动整理文本”和“结构决策结果”。
- 机器可读断言至少支持 `shouldList`、`itemCount`、`containsAll`、`notContains`、`mustPreserveOrder`、`forbiddenRegex`、`expectedSkippedReason`。
- 不涉及剪贴板、窗口焦点和真实 Codex 回填。

### 阶段 1：保守结构规划

目标：先解决误分条、数字误伤和事实丢失。

改动范围：

- 新增 `LiteralSpan` 或等价保护逻辑。
- 新增 `StructureDecision` 或等价内部决策对象。
- 重写 `ShouldPreferStructuredPrompt`，只允许原始口述中的明确枚举、多任务信号或用户明确要求触发分条。
- 调整 `ExtractPromptItems`，只在高置信结构决策下提取列表项。
- 增加 `ValidateStructuredOutput` 或等价输出校验器。
- 将所有可能产出列表的旧路径统一接入结构决策和输出校验。
- 第一轮实现建议拆成最小模块：`LiteralSpanProtector`、`StructurePlanner`、`StructuredOutputValidator`。

分条允许条件：

- 明确枚举词：`第一`、`第二`、`第三`、`第一个`、`第二个`、`首先`、`其次`、`最后`。
- 明确数量意图：`有三件事`、`分成三点`、`有几个点`、`分别是`。
- 多个独立动作：同一段内有两个以上独立命令动词，并由 `另外`、`还有`、`同时`、`下一步`、`最后` 等连接。
- 用户明确要求：`按步骤`、`分条`、`拆成要点`、`列成 1、2、3`。

禁止单独触发分条：

- 日期、端口、版本、型号、时间、金额、百分比、快捷键、路径、文件名、数量范围。
- `一下`、`一个`、`一点`、`第二天`、`三秒钟`、`两三个`、`一两分钟`、`十来个`、`半小时`、`一会儿`、`几个`、`一堆` 等非枚举或模糊数量表达。
- 默认整理规则里出现“拆分、总结、要点、提示词”。

结构决策建议原因枚举：

- `explicit_enum`
- `explicit_step_request`
- `multi_task`
- `sequence_only`
- `protected_number_only`
- `question_intent`

其中 `sequence_only` 默认不强制列表，除非动作独立且可分别验收。

验收标准：

- 数字、路径、端口、版本、快捷键类样例不误分条。
- 明确枚举样例能稳定分条。
- 生成列表时每项至少包含动作或明确对象。
- 事实跨度在输出中完整保留。
- 否定、条件、疑问、不确定性、优先级和专有名词保护用例 100% 通过。
- 输出校验失败时直接回退普通段落，不做局部修补。

### 阶段 2：块级口头禅清理

目标：减少自然口语残留，但不误删语义连接。

改动范围：

- 增加无语义连接块词表，例如 `然后的话`、`就是说`、`怎么说呢`、`反正就是`、`大概就是说`、`这个这个`、`那个那个`、`嗯然后`。
- 对 `就是`、`然后`、`也就是说` 增加上下文保护。
- 增加口头禅清理前后对照测试。

必须保护：

- 判断关系：`问题就是路径不对`。
- 定义关系：`这个变量就是 userId`。
- 解释关系：`也就是说，它不是后台直写`。
- 顺序关系：`先启动服务，然后打开页面`。
- 否定与条件：`不要改代码`、`除非用户确认`、`不是 A，是 B`。

验收标准：

- 口头禅块能被删除或归一化。
- 判断词保护用例 100% 通过。
- 不因清理口头禅丢失否定、条件、顺序或关键约束。

### MVP 补充：最小回填状态闭环

目标：不完整重做 UI，但先解决用户不知道文本在哪里的问题。

改动范围：

- 页面和接口至少区分 `正在整理`、`已回填到 Codex 输入框，可以发送`、`未回填，已复制到剪贴板，请手动粘贴`、`已跳过自动粘贴：未捕获目标 / 聚焦失败 / 用户关闭自动应用`。
- `已回填到 Codex 输入框，可以发送` 只能在确认写入 Codex composer 后显示；只写入剪贴板时不得使用“已回填”。
- 自动应用开启时，持续提醒用户语音结束后等状态变成“可以发送”再点击 Codex 发送。
- 回填接口固定返回 `copied`、`pasteScheduled`、`pastedImmediately`、`pasteSkippedReason` 等状态字段。

验收标准：

- 用户能判断最终文本是在 Codex 输入框、剪贴板还是未成功处理。
- 缺目标或聚焦失败时有明确跳过原因。
- 不新增默认弹窗，不要求用户每次保存样本。

### 阶段 3：回填状态与失败降级强化

目标：让重度用户知道文本在哪里、什么时候可以发送、失败时如何处理。

改动范围：

- 检查并补强页面状态文案：`正在整理`、`已回填，可以发送`、`失败，已复制到剪贴板`。
- `/api/apply-final-text` 在缺少目标或聚焦失败时，返回明确跳过原因。
- UIA 未确认聚焦 Codex 底部 `ProseMirror` composer 时，不发送 `Ctrl+A`、`Ctrl+V`。

验收标准：

- 自动化验证 `sendPaste=false` 时只复制，不安排粘贴。
- 自动化验证缺少目标时返回跳过原因，不误粘贴。
- 人工验证一次 UIA 聚焦失败时不会改写审核页 textarea。

### 阶段 4：显式整理模式

目标：给高级用户强整理能力，但不增加默认认知负担。

模式定义：

- `conservative`：默认。清理明显口头禅、纠错、规范标点；只在高置信度下分条；不主动总结用户没明说的意图。
- `structured`：显式开启。可更主动合并重复背景、拆分多任务、压缩成长提示词；仍必须通过事实保护和输出校验。

改动范围：

- 配置增加 `rewriteMode`，默认 `conservative`。
- 命令行支持 `--rewrite-mode conservative|structured`。
- 网页设置页可选显示模式选择，但不放在主流程第一屏。

验收标准：

- 默认仍为 `conservative`。
- 同一输入在两种模式下的差异可解释、可测试。
- `structured` 不允许丢失事实跨度、否定和条件。

### 阶段 5：可选结构规划器

目标：当本地规则仍不足时，再评估更强的规划层。

准入条件：

- 阶段 1 到 4 已完成并通过测试。
- 本地规则版规划器先跑通接口形态。
- 任何 LLM/API 都必须显式开启，默认关闭。

限制：

- 规划器优先只判断结构，不直接全文重写。
- 云端 API 必须说明文本外发范围、服务方、费用/额度、保留策略和断网降级。
- API key/token 不写入项目文档、样例配置、日志或可提交文件。
- 增加敏感内容拒发/确认门槛：检测到密钥、凭据、长会话片段、隐私路径等内容时，默认本地停止或请求用户确认。

## 5. 隐私与安全门槛

以下门槛是实施条件，不是建议项：

1. 数据最小化：只读 Codex 语音历史最新必要记录、用户主动保存样本、短时旁路确认新增消息。
2. 禁止全量索引 Codex `sessions`，禁止复制完整会话历史。
3. 持续学习、自动应用、随 Codex 启动、发送后旁路确认、LLM/API 的发布默认应保守；如果本机个人配置已开启，文档中必须区分“个人机器当前状态”和“发布默认状态”。
4. 差异日志只写入本项目 `.codex-tmp\voice-feedback\`，继续保留 30 天、20 MB、单日 200 条上限。
5. 候选规则只生成候选文件，不自动改永久源码规则。
6. 不监听键盘、鼠标、屏幕或普通手动输入。
7. 不采集、上传、共享或提交历史转写、会话 JSONL、凭据、API key 或 token。
8. 剪贴板读取必须来自用户显式导入或当前链路需要，不长期轮询普通剪贴板。
9. UIA 聚焦失败时只保留剪贴板，不发送粘贴按键。
10. 启动项、计划任务、随 Codex 启动等系统级行为必须由用户明确确认，并提供关闭/删除方式。
11. 发送后旁路确认只能在回填后短时读取新增用户消息，不得扫描、索引或复制完整会话 JSONL。

## 6. 产品验收指标

第一轮实施的成功标准：

1. 机器可读 golden case 中关键事实、否定、条件、路径、版本、端口、参数的阻断级丢失为 0。
2. 非枚举数字样本误分条率显著下降，目标为 0 个阻断级误分条。
3. 明确枚举样本能稳定输出对应列表。
4. 自动整理文本与用户最终发送文本的差异减少。
5. 默认链路仍保持本地、免费、低延迟。
6. 失败状态清晰，用户能知道最终文本是在 Codex 输入框、剪贴板还是审核页。

## 10. 当前结论

v0.2.0 的主线不是让整理器显得更聪明，而是让它更值得信任。第二轮复议后，当前实施顺序调整为先做“阶段 0 + 阶段 1 + 最小回填状态闭环”：建立机器可读 golden case 和结构决策调试入口，保护事实与语义跨度，重写结构决策，增加输出校验，并让用户明确知道文本在 Codex 输入框、剪贴板还是被跳过。等误分条、事实保护和最小状态可信稳定后，再做块级口头禅清理、完整回填体验和强整理模式。
